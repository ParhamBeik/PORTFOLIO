**Storage:** before changing anything that stores data, read and follow [docs/STORAGE-POLICY.md](docs/STORAGE-POLICY.md). No backups, 100 GB disk shared by four apps; Portfolio history is kept in full and compressed losslessly.

# portfolio-saas

Real-time portfolio tracker for the Iranian market (BRS gold/currency/crypto + TSETMC stocks).
Multi-user from day one: prices are fetched once globally and shared across every user (see README "Why it scales").

**Stack:** React (JS, Vite, Tailwind 4, echarts) + Django REST + PostgreSQL/TimescaleDB + Redis + Celery, Docker Compose.
Full API surface, layout tree, and prod deploy steps: [`README.md`](README.md). Price unit policy: [`docs/REFERENCE.md`](docs/REFERENCE.md).

## Layout

- `backend/config/` — Django project: settings, urls, celery, health, `api.py` (JSON rendering + global error translation), `observability.py` (request id, log filter, Sentry, operator alerts)
- `backend/accounts/` — User model + JWT auth
- `backend/portfolio/` — user-portfolio domain: models (Asset, Account, Holding, Price, Snapshot, LedgerEntry), `services/` (valuation, ledger, performance, returns, diagnostics, optimization), `live/` (price loop: fetcher, extractor, redis_client), `tasks.py` (Celery heartbeat)
- `backend/portfolio/views/` — a package, not a module, split along the groupings `urls.py` already used: `catalog` (assets/accounts/holdings/liabilities), `ledger` (dated events, trades, imports), `valuation` (live value, net-worth series, price screen, performance), `analytics` (risk, optimization, comparison — the throttled and concurrency-capped ones), `admin_ops` (the small `IsAdminUser` surface), and `_common` (request-scope parsing, basis rescalers, the concurrency cap). `__init__.py` re-exports every public name, so `urls.py` and any older importer see the pre-split surface; `tests/test_views_package.py` pins that. A view belongs in the module its URL prefix belongs to — put a shared helper in `_common` only once a second module needs it.
- `backend/marketdata/` — market-history warehouse, separate bounded context: symbol-keyed tables, no user FKs. `fetchers.py` (every BrsApi client, validated against the `endpoints.py` registry), `ingest.py`, `archive.py`/`quota.py` (gap-driven backfill under a request budget), `calendars.py` (which days a market was open), `admin_api.py` (staff-only Ops console plus its urlpatterns)
- `backend/perf/` — latency measurement: `PerfMiddleware` times every `/api/` request into hourly Redis totals, `/api/perf/client/` takes browser page/boot/API timings, a 5-minute task upserts `RequestPerfRollup`, `manage.py perf_report` reads it by route × market state × day type. Hourly rollups only — never a per-request table (storage policy). See `docs/PERFORMANCE.md`
- `backend/tests/` — 21 thematic suites, one per bounded concern; each merges the older single-topic files and keeps their banners
- `frontend/src/` — `pages/` (Dashboard, Ops, MyOptimal, BestOverall, Family, Ledger, Onboarding), `components/ui.jsx` (shared primitives: Card, StatTile, Async, Table, Button…), `components/charts.jsx` (themed echarts wrappers), `api.js` + `useApi.js` (the one fetch pattern), `format.js` (number/date formatting)

Each app has one squashed schema migration (`0001_squashed`, carrying `replaces=`);
marketdata adds `0002_storage_tuning` for autovacuum triggers and the TimescaleDB
tick hypertable. Do not resurrect the one-shot data repairs they replaced — those
have run on every deployed database and a fresh one has nothing to repair.

## Domain invariants (migrated from global learned-patterns — PORTFOLIO-specific, keep here not in `~/.claude/CLAUDE.md`)

- Adjusted prices are read only from `MarketCandle(timeframe="1d_adj")`, never from `DailyStockHistory.is_adjusted=True` (that model now serves unadjusted reads only). Any table feeding the returns matrix must be added to `_price_version_fingerprint()` or cached returns survive new ingests. The fingerprint also carries what a max id cannot see — the integrity gate's last `computed_at` (updated in place), the UTC day (the window slides with it), proxied assets' proxy symbols, and `price_epoch()`, which `bump_price_epoch()` advances on commit for any Price write outside the serialized fetch loop (manual prices, deletions); a new such writer must call it. The matrix cache itself keys on `_returns_version()` (the fingerprint without its `Price` half), and each entry carries the assets its build sent to the live fallback and the newest `Price.id` read *before* the build; `_entry_is_current` rejects it once any of those assets ticks. A tick for an asset with a warehouse series changes no number in the matrix and must not rotate it — that rotation rebuilt every risk/optimization matrix every 20s while the market was open. Keep the live-key record **inside the entry**: a shared "which keys are live" record is a read-modify-write two concurrent builds can lose, serving a frozen column. `optimize()`, MyOptimal and the snapshot sweep keep the full fingerprint: their output also uses live weights.
- In the archive verifier, the read-back in `_fetch_and_ingest` must key on the symbol the ingest path actually wrote, not `state.symbol` — providers canonicalize on write (gold `USDT`→`USDT_IRT`, codal `سامان2`→`سامان`), and a mismatch yields stored=0 against a non-empty expected set: a state that never converges and re-fetches every cycle forever.
- Every price-resolution path — the returns matrix, `value_as_of` (feeds TWR cash-flow boundaries) AND `compute_dynamic_net_worth_series` (feeds the chart) — must bound forward-fill at 5 trading sessions via the one helper `marketdata.calendars.sessions_between()`, and exclude the asset with `price_gap_exceeded` beyond it. A bare `date__lte(...).order_by("-date").first()` silently values today's holding at a delisted asset's last close. Two ways to get the bound wrong, both of which shipped at once: counting **calendar days** (a closure or the Thu/Fri weekend ages a price faster than the market does, so the guard fires early and drops a live holding — this produced a fake two-day portfolio cliff on 2026-07-06/07), and measuring against **one symbol's own rows** (that symbol's latest row is by construction the newest at-or-before `as_of`, so the count is always 0 and the guard can never fire). The calendar must be market-wide and measured in sessions. **Known exception:** `calendars.market_for_asset` has only two calendars, so crypto (which prints 7 days a week) is aged against `gold_currency`, whose Thu/Fri closure makes 5 sessions ≈ 7+ calendar days. The bound is therefore looser for crypto than it reads; it errs toward keeping a holding, never toward dropping a live one.
- `SnapshotListView`'s synthetic fallback must trigger only when there is genuinely nothing recorded. Comparing observed snapshot days against *calendar* days in the window is permanently true — markets are shut Thursday and Friday — so it discarded real history on every request for every holdings-only account.
- Before deploying a squashed migration, diff its `replaces` list against the target's `django_migrations` and confirm the generated file defines `Migration` exactly once. A partially-applied squash is silently discarded in favour of migrations that no longer exist on disk, and a duplicated class definition drops `replaces` entirely — both fail the deploy at `CreateModel`, not at `migrate --check`.
- The F1 TSE price-unit guard belongs inside `daily_returns_matrix()` (`portfolio/services/returns.py`), not in `optimization.py` — all ~8 mixed-unit consumers (diagnostics/AnalyticsView, AssetReturnsView, market catalog, `nightly_asset_metrics`, warmup_cache) route through that one function; guarding only the optimizer leaves the rest computing/caching/persisting cross-unit numbers that may be 10× wrong.
- Commodity/crypto/option history is sourced from live-fetch organic ingest in `portfolio.tasks`, retired from the archive backfill path (`_RETIRED_ARCHIVE_ENDPOINTS` in `marketdata/archive.py`). Never re-add them to `_FULL_HISTORY`/`_ENDPOINT_PRIORITY` or they fall through to the gold fetch branch.
- Monetary storage standardization on Rial was tried (2026-08-05) and **reverted** (2026-08-06): `marketdata/ingest.py` writes every BrsAPI field verbatim with zero multipliers (the warehouse is a faithful copy of the provider payload, unit label included). `marketdata/currency.py:to_toman()` is the only conversion helper, used solely by `portfolio/live/extractor.py` to blend sources into the Toman-denominated `portfolio_price`. Never call it from `ingest.py`; never reintroduce a blanket `x10`/manifest-multiply on warehouse tables.
- All asset-eligibility gating for the returns matrix (`price_gap_exceeded`, `insufficient_history`, `insufficient_coverage` at the 0.90 bar) lives in `_build_returns_matrix()` (`portfolio/services/returns.py`). `optimize()` should only add its own `min_observations`/zero-variance filter before `dropna(how="any")` — a coverage filter there is dead code shadowing the upstream reason codes the UI surfaces.
- When multiple call sites independently re-implement the same validation/threshold check with different magic numbers (e.g. duplicated "bad price" spike-detection heuristics), consolidate into one shared module/constant rather than patching each call site.
- **DRF `CursorPagination` must be subclassed with an explicit `ordering`** on a unique, non-null, monotonic field — use auto-increment `-id`. Never a nullable/non-unique `-created_at`, and never the `-created` default (no model here defines it). It ignores the queryset's own `order_by`, so a non-unique cursor field silently drops or repeats rows across pages.
- **`verified_complete=False` does not mean "damaged".** The archive deliberately re-arms a completed state (`reopen_states_with_gaps`, `promote_priority_tick_windows`) so it picks up sessions printed since the last pass, and `run_archive_state`'s `QuotaExhausted` branch then stamps `last_attempt_at` while leaving `consecutive_failures` at 0 **on purpose** — running out of daily budget is not the job's fault. Any classifier whose last rung is a bare "else → incomplete" therefore reports a re-armed, quota-parked job as carrying gaps: on 2026-08-30 that was 5,978 of 6,383 "partial" jobs — 52.8% of the whole warehouse — every one of them with `stored_rows == expected_rows` and `missing_rows == 0`. Ask the two questions separately: does it owe rows (`missing_rows`), and has it ever landed a payload (`last_success_at`). `coverage_report.classify_archive_state` is the one place that decision lives, `Ops.jsx:archiveJobVariant` mirrors it, and `evidence._claims` must not key the archive claim on the flag either. Staleness (`state_stale_days`) is the real backlog signal — the queue's job is to refetch the symbol that has gone longest without an update, so surface days-behind rather than a boolean.
- **Ops row counts are estimates, and a missing sample is not zero.** `database_counts` comes from `pg_class.reltuples` (and `approximate_row_count` for the tick hypertable) so the request path never COUNT(*)s 58M rows — those estimates are resampled by autovacuum and wobble several percent in **both** directions. Warehouse tables are append-only (nothing deletes from them), so `_clean_count_history` clamps them to a running maximum and leaves user-owned tables alone; add a key to `APPEND_ONLY_COUNT_KEYS` only if nothing can delete from it. Separately, an hour the collector skipped must stay `None` all the way to the chart — `Number(null)` is 0, and `|| 0` in the page or `extent`/`numFmt` in `charts.jsx` turned 4.5% of points into spikes to the floor on a table that only grows.
- **A query on the Jalali `date` cannot prune a hypertable; bound `ts` too.** `ts` is the range-partition key precisely because TimescaleDB cannot partition a varchar, so a predicate on `date` alone leaves the planner no chunk to exclude and it touches all of them. Measured 2026-09-09 on 58M ticks in 1,240 chunks: one symbol-day cost 2,133 ms cold / 318 ms warm by `date`, and 37 ms / 2.2 ms with a `ts` range — same 111 rows; the delete's `EXPLAIN` showed 1,220 seq scans against 19 index scans, and the ingest replace path paid it every time. `jalali.ts_window()` is the one place that bound is declared; it is padded a day either side because it only has to be a **superset** (a delete that misses rows is how the 3.7M duplicate candles were made) and 3 chunks beats 1,240 regardless. It returns `None` for an unparseable day and callers must then fall back to the *unpruned* query — an empty window would delete nothing. Do not add it to a genuinely whole-history query like `_tick_dates_stored`. Caveat: exclusion is plan-time, so a generic plan loses it — the same parameterized query measured 2 ms on custom plans and 3,365 ms on the one execution PostgreSQL planned generically.
- **Disk headroom is measured, never configured.** `project_disk` statvfs's the device (`settings.DISK_USAGE_PATH`, the container's `/`, which is the host data device through overlay2). It used to divide `pg_database_size` — one database's *logical* size — by a hand-typed `VPS_DISK_BUDGET_GB` of 250: on 2026-09-09 that read "257 days until 80%, no alert" on a 147.4 GB device with 31.6 GB free and 11.6 days of headroom. A filesystem fills from everything on it, and the largest consumer here is a neighbouring stack, with this app's own 16 GB of backups second — they grow in lockstep with the database they back up, so the measurement funded its own blind spot. Growth is the **faster** of the device series and our own; underestimating it is the failure this already had. Separately, `operational_health_check` called it bare, so every usage argument defaulted to 0 and the alert was unreachable — check the call site, not only the function.
- **Report the lived value, not the seed setting.** `MARKETDATA_TICK_WINDOW_DAYS` is where a tick state *starts*; `promote_priority_tick_windows` grows `target_window_days` toward `MAX_TICK_WINDOW_DAYS`, so the console must aggregate the column (min/avg/max), not print the setting — it read "90d window" while 31 symbols sat at the 12,000-day clamp. Likewise `first_date`/`last_date` are CharFields where unfetched states hold `""`, which sorts before every Jalali date: aggregate them through `NullIf(field, Value(""))` or "oldest" is permanently blank.
- **Provider quota is per product path, not per API-key string.** Two wallets: AIO (`aio`, 10,000/day) bills `Tsetmc/*`, `Codal/*` and `Market/Gold_Currency_Pro.php`; Market_CGCC (`market_cgcc`, **metered at 1,500/day**) bills `Market/Gold_Currency.php`, `Cryptocurrency.php`, `Commodity.php`. `endpoints.Endpoint.plan` is the mapping authority. `ApiRequestQuota.provider_used` is the panel's own number (read by `reconcile_quota_meters`) and has matched `used` within 5 every day — read it instead of the browser panel. AIO reaching ~9,850 on Thu/Fri is by design (archive takes all budget the live reserve no longer needs). Live reserves only its remaining cadence to Tehran midnight and archive gets the rest; both obey the rolling five-minute window. An archive-triggered breaker must not silence live. Full reference and measured baselines: `docs/QUOTA.md`.
- **`fetch_json` must raise on 5xx.** It historically handled only 4xx and 429, so a 500 fell through to `response.json()` and was returned as if it were data — an exhausted subscription read as a quiet day and marked backfills converged on zero rows. Quota exhaustion is detected on the response *body* (`quota.looks_like_quota_error`), not the status code alone, so an ordinary origin blip cannot pause a whole plan for the day.
- **Keep `ts` out of a unique key on the non-hypertables — and leave it in on the hypertable.** It is a Gregorian mirror of the Jalali domain key, derived by `JalaliDerivedDateTime.pre_save` purely as a partition dimension. `StockTransactionTick` is the one real hypertable, and `uniq_stock_tick_symbol_date_row_time` **must** list `ts`: TimescaleDB rejects a unique index on a hypertable that omits the partitioning column, so migration `0002` drops the plain constraint and recreates it including `ts`. Do not "clean that up" — the migration will fail. It is safe there only because `pre_save` recomputes `ts` deterministically from `date`+`time` on every write, so the same row always lands on the same value. When `ts` sat inside the constraints on `MarketCandle`/`DailyStockHistory`, a later correction to the derivation formula (Tehran midnight is 20:30 UTC the *previous* day) meant every re-ingest inserted a second copy instead of conflicting: 3.7M duplicate candles and 495k duplicate history rows, 380k disagreeing on close price, making risk/return output non-reproducible. `pre_save` now always recomputes and never honours a caller-supplied value. Migration `0005` purged the data; the earlier repair (`0041`, squashed) fixed only the data and the duplicates came straight back.
- **A property is a series of dated marks, not a position.** `HOUSE_MARK_KINDS` (opening + valuation mark) is the one place that pair is declared, and `_projection_state` REPLACES on each mark rather than accumulating. Three rules follow, each of which shipped broken: which kind to write is an **account**-level question — every opening carries `tracking_started_at`, so a property added after tracking began must be a `VALUATION_MARK`, not a second opening (deciding per-asset raised a `LedgerError` that escaped as a 500 on the holdings screen the moment a portfolio held two properties); deleting a property must reverse **every** live mark, since reversing only the opening leaves later marks to rebuild the holding on the next replay; and any endpoint that shows `area_sqm` must also accept it — `LedgerEntryPatchSerializer` took the field, dropped it, and answered 200, so a resize looked saved and was not.
- **`archive_paced` and `live_reserved` are retryable.** `PACING_REASONS` is the authority. Both clear as time advances because the live reserve is forward-looking; plan/bucket exhaustion remains day-scoped. If the reserve becomes static again, remove `live_reserved` from that set in the same change.
- **Dispatch no more archive states than there is quota to spend.** `archive_tick` bounds its batch by `sum(archive_capacity().values())`, not just by batch size and queue depth. A surplus task cannot fetch anything: it wakes, loses the race for the last request and re-parks, costing a database round trip and a log line each time. On 2026-09-06 that was 101,098 no-op runs against 4,139 real fetches — 96% of all archive executions, drowning the 4% that mattered.
- **A workflow log line must name both ends of the pipe.** `source` and `destination_table` are on `WorkflowRun` *and* on the stdout summary, plus `cid` to join them. `_ledgered` derives `source` from `endpoints.source_for()` — the registry is the single declaration of an endpoint's provider path and plan, so a hand-typed source can only drift. Archive destinations come from `archive.ENDPOINT_DESTINATIONS`, which mirrors `_fetch_and_ingest`'s branches; the whole archive used to report `ArchiveFetchState`, which is the bookkeeping row it updates and never where rows land. Pass `source=""` explicitly for schedulers, prunes and aggregations that have no origin.
- **Coverage counts jobs; the census counts symbols.** Every number in `coverage_report` except `build_symbol_census` counts `(symbol, endpoint)` states, so a symbol with eight endpoints contributes eight rows and "1,331 pending" reads as a symbol count when it is not. `classify_archive_state` tests `blacklisted`/`suspended_at` **before** `verified_complete`: a symbol the archive has given up on is neither coverage nor backlog, and both flags sat on the model for weeks with no status naming them, so every unfetchable symbol was counted as whatever its stale row counts implied. `Ops.jsx:archiveJobVariant` mirrors the order, and the API must serialize both fields or the console classifies on `undefined`.
- **A retired endpoint needs three switches, not one.** Dropping it from the seed dict only stops *creation*: rows an earlier deploy made keep polling forever. `live_states._RETIRED_LIVE_ENDPOINTS` force-disables them on every `ensure_live_states` and records why in `last_error`. `ime_futures`/`ime_options` were retired this way on 2026-09-06 (every row rejected on ingest, billed TSETMC on a 900s cadence, read by nothing); `etf_nav` before them. Codal is different — it is *gated*, not retired, by `settings.CODAL_ENABLED`, which controls the queue route, the beat entry and `archive.disabled_endpoints()` together; its states are left untouched so they resume when the flag flips.
- **The integrity gate and `_build_returns_matrix` must agree.** A leading run of absent sessions is the *absence* of history (newly listed), not a hole in it — `integrity.compute_symbol_integrity` clamps to `first_observed` exactly as `returns._gap_profile` does. Per-symbol halts come from `calendars.symbol_halt_days` (zero volume AND zero trades for one symbol while the market traded), the single-symbol twin of `market_closure_days`. `excessive_rejections` needs both `MIN_REJECTIONS_FOR_GATE` and the ratio — a bare 1% bar over a ~112-session window means "one bad day disqualifies you" and dropped 208 symbols. `insufficient_backfill` (our warehouse is incomplete) is a distinct reason code from `low_coverage` (the data is gappy); conflating them reported 79% of the universe as corrupt when most of it was simply un-fetched.
- **An email address is one identity, stored lowercase.** `UserManager.normalize_email` folds the WHOLE address (Django's folds only the domain), and `get_by_natural_key` normalizes then matches **exactly** — exact, not `iexact`, so the unique index is still used, which is only sound because every write is canonical. Anything that creates a user must go through the manager; a bare `User.objects.create(email=...)` reintroduces the split. `RegisterSerializer` canonicalizes in `to_internal_value`, not `validate_email`, because DRF runs `UniqueValidator` inside `run_validation` and a late normalization turns "address already taken" into an IntegrityError 500. Before this, `Case@x.com` and `case@x.com` were two members with two empty portfolios while password reset (`email__iexact`) already treated them as one.

## Linting

Both linters are **correctness only** and both gate CI. Neither enforces style:
this codebase has a consistent voice already, and a lint run that mostly prints
opinions gets ignored — which costs the rules that matter.

- `backend/ruff.toml` — pyflakes-class rules plus syntax. It exists because
  `logger` was undefined in two `except` handlers in `views/analytics.py`: the
  handlers were written to degrade gracefully and instead raised `NameError` and
  500'd. F841 (assigned but never used) is deliberately **off** — a test
  creating a row for its side effect is the fixture, not a mistake.
- `frontend/eslint.config.js` — `no-undef` is the whole reason it exists. Rollup
  resolves module specifiers, not identifiers, so a component referencing a name
  nothing imported builds clean and throws `ReferenceError` in the browser.
  `eslint-plugin-react-hooks`' v7 recommended set is deliberately **not** taken:
  `set-state-in-effect` and `refs` flag working code and each would need a
  refactor. Add a rule to either config when it would have caught a real bug.

## Frontend conventions

- Pages compose `ui.jsx` primitives (`Card`, `StatTile`, `Async`, `Table`, `Button`, `PageHeader`, `Disclosure`) and write no bespoke panel/loading/error markup.
- Every element a test or screen reader needs takes `testId` → `data-testid="<page>-<thing>"`, lowercase-hyphenated.
- Data fetching goes through `useApi(fn, deps, opts)` (`useApi.js`) — the one fetch pattern (loading/error/poll/pause-when-hidden). Never hand-roll a fetch effect.
- `res.statusText` is always `""` over HTTP/2, which is what production serves. Never use it as an error message's only fallback, or every unexplained failure reaches the user as a bare "Something went wrong."
- Tooltip formatters in `charts.jsx` return **HTML**, and the labels they print (holding nicknames) are user-typed. Everything user-supplied goes through `esc()` — an unescaped `<` silently swallows the row.
- Charts go through `components/charts.jsx` wrappers only — pages never `import echarts` directly and never write a hex color; colors come from `var(--c-*)` tokens in `index.css`, resolved via `useChartTokens()`.
