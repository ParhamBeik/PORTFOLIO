# Portfolio and research warehouse baseline — 2026-09-25

This is an evidence ledger for the running VPS at `45.139.10.12` and the implementation branch `codex/trustworthy-research-foundation`. It is a baseline, not a claim that the financial warehouse is already suitable for investment decisions. The complete public-table column inventory is [production-schema-2026-09-25.csv](production-schema-2026-09-25.csv). That inventory contains names and types, no account records or secrets.

The companion [product contract](product-scope-2026-09-25.md) maps the user's protected views, daily research workflow, candidate pages for retirement, and question families to explicit data gates.

## Product boundary

Preserve the Activity ledger and the Portfolio, Net Worth, Allocation, Holdings, and Performance views. The current Markets, Guidance, risk, optimization, and operations surfaces are candidates for consolidation or removal after their data dependencies and users are checked. A successful rebuild means a user can ask an ad hoc financial question, inspect the exact source and calculation behind every reported number, and see a clear refusal when the warehouse cannot support the answer. Personal portfolio state and the shared research warehouse remain separate.

The attached `financial_agent_warehouse_plan.md` is a proposal to test, not a schema specification to implement literally. In particular, a single USD rate applied to every statement line would mix stock and flow measures. IAS 21 distinguishes transaction-date rates for income and expenses from closing rates for balance-sheet items; a period average is only a practical approximation when rates do not fluctuate significantly. An economic free-market-USD comparison also needs its own explicit convention and may differ from an accounting presentation. Store the original Rial fact, rate series, source, and conversion method before publishing a USD-derived number. [IFRS IAS 21](https://www.ifrs.org/content/dam/ifrs/publications/pdf-standards/english/2024/issued/part-a/ias-21-the-effects-of-changes-in-foreign-exchange-rates.pdf?bypass=on)

The plan's example “net margin in USD” is not a distinct financial ratio when profit and revenue are translated consistently: the common currency factor cancels. The real questions are which profit and revenue periods and consolidation scopes are comparable, and whether separate translation dates would change the economic comparison. A cross-industry ranking cannot treat a bank's interest income, an industrial company's sales, and a holding company's investment gains as one interchangeable revenue field. Asset-class-specific facts and formulas remain separate; comparisons state their eligibility rules rather than filling absent fields with zero.

The proposed `StandardIncomeStatement` labels fields `revenue_rial` while its heading says the raw values are **millions of Rials**. That naming error would silently overstate or understate a downstream conversion by 1,000,000. The implemented candidate facts keep `unit="million_rial"` beside the exact source cell; any later normalized table must carry an explicit scale rather than rely on a suffix.

## Recovery state

The 2026-09-25 encrypted database dump (2,807,377,392 bytes; VPS file completed 03:22 UTC) is on the Mac and an external drive. SHA-256 matched the VPS copy, and decrypt streamed through `pg_restore --file=/dev/null`. The passphrase is separate, mode 0600. A full **isolated** restore on Mac PostgreSQL 16.15 / TimescaleDB 2.17.2 completed with `pg_restore --exit-on-error` and `timescaledb_post_restore()` true: 57 public tables, 5,062,854 daily-stock-history rows, 4,516,266 market candles, 93,125 Codal reports, 279,338 Codal artifact records, 1,461,302 legacy facts, and 134 portfolio ledger entries. Today’s live database later reached 105,160 Codal reports and 314,254 artifact records; those newer ingestions are outside this nightly recovery point. This is a successful database restore drill, not zero-loss recovery.

A Mac pull copied the latest encrypted dump, checked its VPS SHA-256, decrypted it through local `pg_restore`, and published a same-hash off-host receipt back to the VPS. A macOS LaunchAgent runs this pull hourly when the Mac is available. The draft host check rejects a missing receipt or a receipt for different bytes; production has not been redeployed with that check yet. An offline Mac can still leave the newest nightly dump without an off-host copy, which must alert rather than be called protected.

The restore-drill script now streams the encrypted archive and uses Timescale's pre/post-restore functions. It requires an explicit isolated `TEST_PG_HOST` and the source `RESTORE_TIMESCALE_VERSION`; it refuses to replace an existing database. The manual full restore above exercised the same sequence. The script itself has only received syntax and guard checks so far.

The broker cutover is guarded in `scripts/deploy.sh`: it now checks nonempty legacy queues for a running, unpaused consumer **before** backup/build or any API stop; it then stops the old Beat and API producers, lets old workers drain Redis DB 2 queued and unacknowledged messages, and aborts with the old services restarted if a five-minute drain cannot complete. This causes API downtime during the first cutover. The live preflight currently fails by design: 100 archive jobs have a paused worker and 200 Codal jobs have no worker. The active portfolio configuration enables Codal, and 2026-09-26 VPS HEAD probes to `codal.ir` and `search.codal.ir` returned HTTP 200; that does not prove individual artifact URLs or justify running the old parser that conflates source and inferred categories. Resolve the queue/worker state against the corrected release before cutover. The new broker uses Redis AOF (`appendfsync everysec`) and `noeviction`; task results remain disposable in the cache Redis. This has passed static Compose validation but not a live cutover. AOF with one-second fsync is a bounded durability improvement, not a zero-loss guarantee.

An alternative [queue-copy handoff](../broker-handoff.md) now has a tested, read-only-by-default utility that verifies and copies the three legacy queue lists to an empty durable broker, leaving the source intact. The draft deploy script integrates it behind an explicit `BROKER_HANDOFF_MODE=copy`, with `ARCHIVE_WORKER_ENABLED=0` and `CODAL_WORKER_ENABLED=0` required for the current paused/absent consumers. Copy failure resumes only services that were running before the attempt. The real production queues have **not** been copied; the mode has a fake-Docker rollback test and an isolated Compose scale-to-zero probe, not a live cutover. The default drain path still cannot clear the present production preflight.

The external Codal raw-volume archive has two compressed parts with verified SHA-256 sums and a complete readable tar listing (536,728 entries; 225,185 object metadata files). ## Target architecture and sequence

1. **Recovery and operating safety.** Database and sample Codal S3 restore drills passed; run and schedule the repeatable object archive, recording each recovery point. Deploy and verify the persistent broker with its guarded queue drain. Keep production on its current version until broker and deployment checks pass.
2. **Trustworthy source layer.** Preserve immutable artifacts and parser runs. Certify monthly sales first, then income statements and balance sheets template by template. Model reporting periods, standalone/consolidated scope, corrections, units, source cells, and abstentions. Never equate a parsed number with a certified fact.
3. **Comparable market layer.** Resolve symbol identity and industry membership over time, corporate actions, adjusted prices, cash USD versus USDT, and daily FX coverage. Treat flow translation, balance-sheet translation, and investment returns as different operations. Publish a derived metric only with formula/version and source rows.
4. **Research workspace.** Deterministic tools retrieve and calculate; the model selects only within returned evidence. The current draft offers monthly sales observations and latest certified standalone/consolidated income figures, with period and audit status. It still abstains from USD, peer, valuation, and cross-company rankings. One research run has an in-app, user-selected USD spend ceiling and a separate server-side daily ceiling. The GapGPT key, model, URL, and token-price settings are projected from the existing News project on the VPS; the active portfolio deployment environment has the future secret mount and server caps prepared, but the current production containers have not been restarted with this branch. No key reaches the browser or repository. Reserve a conservative maximum before each provider call, record actual usage even if the answer is rejected, and show cost and evidence beside the answer.
5. **Product simplification.** Keep the protected portfolio views and Activity. Make company exploration and research the main shared-data path. Prune or merge other routes only after verifying that no distinct trusted workflow remains. Validate desktop/mobile use and run paired source-to-answer examples before release.

Release examples: (a) a monthly-sales answer links to the exact Codal cell and survives a corrected filing; (b) a five-year USD-growth query reports its FX convention and excludes missing dates; (c) a net-profit ranking refuses to run until statement line items and periods are certified; (d) portfolio performance still reproduces ledger cash flows, rights issues, and reversals; (e) a restored database plus Codal object sample can reproduce a displayed answer. No AI call is needed to fetch or calculate these facts.
