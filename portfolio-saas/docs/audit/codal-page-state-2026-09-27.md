# Codal announcement state accuracy — 2026-09-27

A read-only production query found 1,134 `codal_announcements` archive states. Of those, 760 were marked complete while their `stored_rows` was below the actual announcement count for the same symbol; 765 had `stored_rows <= 20` despite more than 20 stored announcements. The state symbols together held 103,573 announcement rows, while their states reported 37,375. All 1,054 populated Codal `first_date` values failed the `YYYY-MM-DD` date shape. Production also contains 77 `(code, publication date, publication time)` groups shared by more than one symbol, so issuer identity belongs in the read-back key. These are state/reporting defects, not evidence that stored announcement rows were lost.

The current eligible TSETMC-stock catalog contains 1,593 symbols. Only 789 have any announcement under the same symbol in this warehouse; 776 have at least 100. Only 24 have a stored announcement published on or before 1400-07-05 (five years before the scan), and 11 on or before 1395-07-05 (ten years). These publication-date counts do not establish financial-period or statement-template coverage, and symbol renames may leave older filings under another identifier. They show that the present five-page cap cannot answer the requested five- to ten-year questions across the catalog.

The old refresh fetched deeper pages only while the existing row count was below the configured target. Once a symbol held the target, the next refresh fetched page 1 alone and overwrote the state's multi-page counts with page-1 counts. The generic date assignment took the minimum of a `code_date_time` key rather than the publication date. The draft fix rereads every page of the configured bounded window on each refresh, checks the provider's distinct row count and date validity, verifies issuer-aware keys against PostgreSQL, and stores publication-date bounds. An incomplete or shifting page set fails the refresh instead of claiming complete coverage.

The default target remains five pages (at most 100 newest announcements per symbol). A complete state after the fix means those **bounded pages** were checked; it does not mean the issuer's complete Codal history or five- to ten-year financial coverage is present. Raising the page cap increases both initial backfill and seven-day refresh request cost, so use the provider quota and a measured historical acquisition plan before changing it. Production states will reflect the corrected counts only after the branch is deployed and each symbol is refreshed.
