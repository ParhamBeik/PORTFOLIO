# Legacy Celery broker handoff

Production still uses Redis DB 2 for both task messages and disposable results. The new Compose file has a separate Redis 7.2 broker with AOF and `noeviction`. On 2026-09-26 the old `archive` queue held 101 messages while its worker was paused, and `codal` held 200 messages without a worker. The default drain cutover must therefore abort before stopping the API.

`scripts/copy_celery_queues.py` is a **prepared, unexecuted production handoff option**. It copies the raw Redis lists `live`, `archive`, and `codal` into an empty broker without parsing task arguments, changing order, deleting the old lists, starting workers, or making provider calls. It refuses unacknowledged tasks, unexpected queue lists, an occupied target, or a target without AOF and `noeviction`. It checks length and SHA-256 of every message before and after the copy, forces a target disk snapshot, then writes a new mode-0600 receipt containing counts and hashes only. An isolated two-Redis test covers exact binary payloads, source preservation, duplicate-target refusal, and unacknowledged-task refusal.

The copy does **not** itself make a cutover safe. Beat, API producers, and every old worker must be stopped after in-flight tasks finish; otherwise a new message could arrive while copying. The target's workers must stay stopped until the receipt is checked. Once any new worker starts consuming, restarting an old worker against the preserved source lists can duplicate work. A failed copy leaves the target unsuitable for cutover; clear only that isolated target after confirming the source remains intact. Never delete the old queues as a shortcut.

Before production use, integrate this handoff into `scripts/deploy.sh` with a rollback boundary and a deliberate decision about the paused paid archive worker. The corrected Codal worker may process carried messages only after the source-category fix is deployed and an artifact sample is checked. The current script retains its fail-fast guard; it does not invoke the copy utility. The production queue has not been copied or drained by this work.
