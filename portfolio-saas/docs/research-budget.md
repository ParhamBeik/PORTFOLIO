# Bounded research and News GapGPT settings

The first research tool answers questions about **one TSE company's source-reconciled monthly sales or certified income and balance statements**. The model sees the question and the names of available observations; it returns observation IDs only. The server computes every value, stores the exact Codal evidence snapshot, and makes the run available to its owner at `GET /api/research/runs/{id}/`. Net profit and margin answers require a certified issuer, period, scope, unit, and source cell. USD, industry peers, crypto, and causal explanations abstain until their data/tool contracts are certified. A refusal from those boundaries makes no provider call.

The saved-answer link in Explore reloads that run and recalculates its selected observations against the current filing and parser rules. `evidence_state=current` means the selected statements and source metadata still match; `changed` means they do not, and `unverifiable` means the old scope or stock is no longer available for that check. The historical answer and cost record remain intact. This check does not reread every archive byte; the archive download performs a fresh size and SHA-256 check before serving a filing.

The browser lets the user set a maximum USD budget for each run. PostgreSQL reserves a conservative one-call estimate before contacting GapGPT, with a 10× tariff cushion and a separate daily cap across portfolio users. A provider-reported cost is recorded even when its answer is rejected. If the request times out, its reservation remains charged against that day because the provider may still bill it. A provider price change can still exceed an estimate, so an overrun is recorded and the answer withheld; the app must never claim an absolute billing guarantee it cannot enforce. The portfolio daily cap is separate from the News project's own budget even though both use the same provider key.

## Production configuration

1. As root on the VPS, run `python3 deploy/sync_gapgpt_config.py` from the deployed portfolio repository. It reads `/opt/apps/news-intel/deploy/.env` and that deployment's `backend/config/settings/base.py`. It writes only the GapGPT key, URL, model, and input/output tariff into `/opt/apps/portfolio-secrets/gapgpt.env`, owned by container UID 1000 with mode 0600. No value is printed.
2. Set `GAPGPT_CONFIG_HOST_FILE=/opt/apps/portfolio-secrets/gapgpt.env` in portfolio `.env.production`. The backend alone mounts it read-only; an absent setting uses a checked-in empty file and disables AI calls. Set `RESEARCH_MAX_RUN_USD` and `RESEARCH_DAILY_BUDGET_USD` to the desired server caps. Users choose a lower per-run amount in the application.
3. Verify the settings API reports `provider_status=ready` and the expected model, without returning a key. Restart the portfolio backend after re-projecting a rotated News key because Docker's file bind mount can keep the former inode. No other portfolio service needs the provider key.

The source of truth for provider identity and tariffs is the News deployment, not a copied API key in the Git repository. Check the provider's current tariff before enabling research: when the News `.env` omits token prices, the projection uses the defaults in the deployed News settings code. The model is contacted once per supported run, with no retry loop. Do not test with a live key until the database backup and Codal artifact restore gate is passed.
